# Contributing

Thank you for helping make proposal work simpler and clearer.

1. Open an issue describing the problem or proposed improvement using **fictional** example data.
2. Fork the repository and work in a focused branch.
3. Run `npm run verify` before submitting a pull request.
4. Include keyboard and mobile behavior in UI change descriptions.
5. Preserve the local-first design: no trackers, unsolicited network calls, or unnecessary runtime dependencies.
6. Do not attach real client proposals, addresses, personal contact data, API keys, or credentials.

See [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).
